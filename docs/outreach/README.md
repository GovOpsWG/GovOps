# Outreach

How to find the GovOps Working Group and take part in its work.

## Where the working group talks

| Channel | Use it for |
|---|---|
| [GovOps LinkedIn Group](https://gluu.co/govops-group) | Announcements, discussion, and meeting notices |
| [GitHub issues](https://github.com/GovOpsWG/GovOps/issues) | Proposing metrics, catalog fields, and architecture changes |
| [GitHub pull requests](https://github.com/GovOpsWG/GovOps/pulls) | Contributing document changes |

## How to contribute

Every deliverable in this repository is a plain Markdown file. You can edit one directly in the
GitHub web editor, with no local toolchain. [CONTRIBUTING.md](../../CONTRIBUTING.md) has the
details, including how to sign off a commit.

Good first contributions:

- **Propose a metric** using the [template](../metrics/README.md#10-how-to-propose-a-metric). The
  metric set has a documented parking lot of candidates held for v2, each with the reason recorded.
- **Answer an open question.** The [ACC design](../acc/authorization-capability-catalog-design.md)
  and the [metrics front matter](../metrics/README.md) both close with open questions.
- **Report a gap.** If the architecture does not cover a system you have to govern, open an issue
  describing it.

## Who the work is for

The proposal names the audiences the working group wants feedback from: application security teams,
identity practitioners, authorization vendors, auditors, GRC professionals, cloud security teams,
and AI governance practitioners. If you are one of those, your review is the contribution.

## Talking about GovOps

The one-line description:

> The GovOps Working Group advances continuous, policy-driven governance for authorization, risk,
> and trust across open source, cloud, and agentic systems.

The three steering responsibilities GovOps names are **risk management**, **accountability**, and
**observability** — measure risk, transparency, and accountability.
